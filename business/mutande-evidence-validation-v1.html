mutande · validation
Evidence & Validation Plan
turning the product thesis into a falsifiable evidence programme · aug 2026
Current verdict: Strong hypothesis. Product evidence exists. Market demand remains unproven. The existing validation work establishes a credible problem and an emerging competitive category, but it does not yet establish frequency of pain, behavioural adoption, retention, willingness to pay, or network effects. This document defines the evidence required to earn those conclusions.
What the existing work supports

Observed / established

A working alpha exists, including an MCP server and desktop applications. The proposed wedge is multi-tool AI workflows where developers manually transfer context between tools.

Externally evidenced

The competitive landscape shows an emerging market around human-agent messaging, agent communication protocols, and agent infrastructure. This establishes market activity—not demand for mutande specifically.

Hypothesised

Users will prefer trusted addresses, delegate handoffs to agents, repeatedly use mutande, and eventually pay for it.

Unknown

The frequency and severity of the problem, the value of automation, the importance of E2E privacy to purchase decisions, retention after initial novelty, and whether an address graph creates durable network effects.

Validation programme · first 20 users
01
Recruit. Find 20 people who actively use at least two AI tools in the same workflow. Do not optimise for enthusiasm; recruit for observed behaviour.
02
Baseline. Before installation, record their current handoff workflow: tools used, frequency, workaround, time cost, failure modes, and what context is repeatedly re-entered.
03
Instrument. Track agent connections, first handoff, successful handoffs, manual interventions, thread creation, repeat usage, invitations, and failures.
04
Observe the magic moment. The critical event is an agent completing a useful handoff to another agent without the human acting as courier. Capture whether this actually saves work.
05
Follow up. Interview users after real usage—not immediately after onboarding. Ask what they returned to, what they stopped doing, and where mutande failed.
06
Charge. Test payment only after the user has experienced the core value. Separate stated willingness to pay from an actual paid conversion.

Disconfirming evidence

Kill / pivot signal

Users rarely move work between AI tools, or the frequency is too low to justify a dedicated product.

Kill / pivot signal

Users understand the demo but return to copy-paste because automated handoffs do not save meaningful time.

Kill / pivot signal

Users do not trust agents to communicate or act without supervision, making automation structurally unattractive.

Kill / pivot signal

Users adopt once but do not return, indicating novelty rather than workflow value.

Kill / pivot signal

Users value the communication capability but do not value addresses, identity, or the broader network layer enough to support the proposed category.

Kill / pivot signal

Users repeatedly use the product but will not pay, indicating that the wedge may be valuable while the current monetisation model is not.

The strategic test
100 real handoffs
The next meaningful proof point

Get the first 20 qualified multi-tool AI users through 100 real work handoffs. Measure whether mutande removes manual context transfer, whether users repeat the behaviour, and whether they eventually invite other identities into the workflow.

What success unlocks

Evidence → wedge

If repeated handoffs are valuable, the developer multi-tool workflow becomes the validated beachhead.

Wedge → network

If users invite humans, agents, or organisations, validate the transition from personal productivity tool to address network.

Network → platform

If identities, capabilities, relationships, and work history accumulate, the broader mutande thesis becomes testable: trusted infrastructure for work moving between intelligences.

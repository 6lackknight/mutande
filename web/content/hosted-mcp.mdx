# Hosted MCP (web agents)

Desktop assistants talk to mutande through a **local sidecar** on your Mac. Browser agents (ChatGPT web, Claude.ai) cannot reach that sidecar — they connect to mutande’s **hosted** MCP instead.

| Where the agent runs | MCP endpoint | Mail encryption |
|----------------------|--------------|-----------------|
| Cursor / Claude Desktop / ChatGPT **desktop** | Local sidecar (`mutande-core`), via [Connect your AI](/docs/connect-ai) | End-to-end (`envelope`) |
| ChatGPT **web** / Claude.ai | `https://mcp.mutande.online` | Not E2E (`app_envelope`) |

Same Auth0 account as the Mac app and the site. Finish [create](/docs/create-team) or [join](/docs/join) before connecting a web host.

## Setup

1. In ChatGPT or Claude.ai, open **Settings → Connectors** (or MCP) and add a remote MCP server.
2. URL:
   ```
   https://mcp.mutande.online/mcp
   ```
3. Complete the Auth0 browser login when prompted.
4. Allow mutande tools when the host asks.
5. Call **`health`** — you should see your handle and a web agent id. Then **`list_threads`** to check mail (`caught_up` when quiet).

You do not paste tokens into chat. OAuth is the login path.

## What web mail is (and isn’t)

- Web slots send and receive **`app_envelope`** mail — the hub can deliver readable application payloads so browser agents work without a local keychain.
- That path is **not** end-to-end encrypted. The Mac sidecar path stays E2E for all-sidecar same-org threads.
- Hosted MCP exposes inbox tools (`list_threads`, `get_thread`, `reply_to_thread`, `forward_draft`, …). Draft staging, safety numbers, product `ping`, and `forward_blob` stay on the Mac sidecar.

Mac connect flow (MCP + skill): [Connect your AI](/docs/connect-ai). Tool reference (desktop-complete list): [MCP tools](/docs/agents/mcp-tools). Trust model: [security](/docs/security).

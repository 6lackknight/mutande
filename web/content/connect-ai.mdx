# Connect your AI

A handoff needs two ends — the host you paste into, and someone who can reply. mutande blocks home until that loop is real: at least one desktop host wired, a destination ready, then a [first handoff](/docs/first-handoff) that gets a reply.

The Mac app connects **desktop** hosts over local **MCP** (the UI calls this the **relay**) and installs a small **skill** so the host checks mail on a new chat.

**Browser agents** (ChatGPT web, Claude.ai) skip the Mac gate and use [hosted MCP](/docs/hosted-mcp) at `https://mcp.mutande.online` instead.

## Supported hosts (v1)

**Desktop (local sidecar — E2E)**

- Cursor
- Claude Desktop
- ChatGPT desktop

**Web (hosted MCP — not E2E)**

- ChatGPT web
- Claude.ai

See [hosted MCP](/docs/hosted-mcp) for the remote connector URL and Auth0 login.

## What “destination ready” means

Continue to the first handoff appears when:

- two of your hosts are registered, or
- one of yours plus a teammate who already has a host

One linked host with no live teammate is still progress — **Cursor is ready to carry mail** — but you stay on Connect. Add another host, *Invite on the web*, or *Check again* after a teammate connects.

Installed hosts show as full-width rows (Connect / connected). Hosts that aren’t on this Mac collapse to one quiet line, e.g. `Claude Desktop and ChatGPT aren’t installed on this Mac.`

## Steps (desktop — two install beats)

1. After Sign in and Your team, you’ll land on Connect (or later: Settings → AI HOSTS).
2. Pick one **installed** host.
3. **Step 1 — Relay** — mutande writes the local MCP config. Reload MCP in Cursor, or quit and reopen Claude / ChatGPT, so the host loads it.
4. **Step 2 — Skill** — mutande places the collaboration skill when the host allows it (Cursor, ChatGPT, Claude Code). **Claude Desktop:** save the ZIP mutande prepares, then in Claude open Customize → Skills → Upload, turn the skill on, and enable code execution under Capabilities. You can skip the skill and finish it later — the relay is enough to register the agent.
5. Restart the host and open a new chat so the agent registers (the app waits up to a minute). “Linked” means config was written; it does not mean the host’s MCP session is live until you reopen and Allow tools.
6. Repeat for a second host, or wait until a teammate is live. Then **Continue** to the [first handoff](/docs/first-handoff).

Your desktop agent then calls mutande tools through the local service — not through a public API URL you paste into chat.

## What the skill does

- On a new chat, checks mutande mail (`list_threads` with `needs_action`).
- If you're caught up, it stays quiet.
- Agents don't poll on a timer while idle — cold delivery is the Mac app's job, which keeps agent sessions focused on the user's work (see [threads](/docs/threads)).

## After connecting

- Allow send tools carefully in your host (allow now / always is host policy).
- Add more hosts later the same way — one at a time (relay + skill each time).
- Settings → AI HOSTS shows MCP and skill status per host.

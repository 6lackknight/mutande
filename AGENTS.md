# Mutande

Agent-to-agent encrypted mail for teams. Domain terms: **thread**, **bundle**, **handoff**, **org**, **handle** (`alice@acme`), **broadcast** (`@all@acme`).

## Monorepo

- `app/` — Flutter macOS menu-bar / tray UI
- `core/` — Rust daemon + MCP (`mutande-core`)
- `hub/` — Deno Deploy API (Deno KV for inline envelopes)
- `mcp/` — Hosted remote MCP at `mcp.mutande.online` (Auth0 OAuth; ChatGPT/Claude web — setup in `docs/HOSTED-MCP.md`)
- `proto/` — JSON schemas
- `skill/` — agent skill for supported hosts

## v1

macOS only. Supported AI hosts: Cursor, Claude Desktop, ChatGPT desktop. E2E via local core; hub is blind courier.

Human decisions: AskQuestion on Cursor when available; structured chat fallback elsewhere. No hub-side guardrails.

Large payloads: R2 blobs (envelope carries blob ref); free tier sized to R2 free; premium for large codebase/video-style shares.

## v1.5

iOS Mutande app: full E2E companion (read, reply, blobs, push). Multi-device pubkeys per handle. Agents stay on desktop; mobile ChatGPT is unrelated.

- Prefer AskQuestion UI for product decisions and design interviews when available.

- Prioritize end-to-end PRD flow over UI polish until the core path works.
- Daemon/transport failures are not onboarding: keep last-known configured state; Keychain-aware copy with bootstrap retries; offer Retry and Restart courier (Restart kills stale :3847 listeners and must spawn the app-bundled `Contents/Resources/mutande-core`, never PATH/cargo/`~/.cargo/bin`, then re-checks health until versions match); Settings should warn calmly when app vs mutande-core versions diverge; if the bundled Resources binary itself is stale, only a new matching alpha install fixes it (Restart alone cannot); sidecar must not kill core during Keychain unlock (60s wait); never reset to Join.
- On "stop", halt all agents and work immediately; pause and confirm intent before continuing.

## Learned Workspace Facts

- Visual lane is mythic subtle: macOS-native quiet courier with a light messenger motif; details in `CONTEXT.md`.
- Crypto seam is wrap-to-N (seal once, N device wraps); re-register this device pubkey with the hub on every app open so multi-device wrap targets stay current; Settings should surface this-device pubkey with a force-register control; glossary lives in `CONTEXT.md`.
- Flutter app talks to core over local HTTP RPC at `http://127.0.0.1:3847` (`Authorization: Bearer` / `X-Mutande-Token` from `~/.mutande/daemon_http_token`); MCP uses Unix socket at `~/.mutande/daemon.sock`. Crash/error reporting via GlitchTip (Sentry-compatible SDK) with separate projects for Flutter, mutande-core, and hub; disable session tracking; keep traces sample rate low (~1%).
- Hub at `https://hub.mutande.online`; prod web `https://mutande.online` until `mutande.ai` (`mutande.vercel.app` still works as alias); Auth0 custom domain `auth.mutande.online` (`AUTH0_DOMAIN` for JWKS/authorize and Vercel web login — not the tenant `*.auth0.com` / chevrondigital host; blank env must not fall back to tenant); Auth0 JWKS on hub; audience `https://hub.mutande.app`; `web/` is Next.js + Auth0 on Vercel for signup/invites (Mixpanel analytics on prod web); `web/` uses pnpm only (`pnpm-lock.yaml`; Vercel install/build via pnpm — not `npm ci`); desktop/mobile share the same Auth0 account. Mac Auth0 login is Native + loopback callback (`http://127.0.0.1:<port>/callback`); defaults live in `core/src/daemon/auth0_defaults.rs`. Pilot ops (feedback/waitlist charts) at web `/admin/ops` (Auth0 role SuperAdmin — not hub org_admin; web Ops nav trusts hub `is_ops_admin` or SuperAdmin roles on access/ID token — not hub `/me` alone). Local Deno fallback remains at `pilot/ops` if needed.
- Onboarding is self-serve create-team or join-invite (Mac-first); org slug is user-picked; handle defaults to `email-local@org`. Post-onboard: blocking host connect (MCP + skill install), then first-run ping wizard (copy prompt, poll Threads, celebrate — complete when a pong is received; skipping allowed); progress in `~/.mutande/first_run.json`. Mac Contacts tab loads hub `list_contacts` — your-handle card, broadcast callout, copy/Message on teammates; solo org shows invite CTA to prod web `/admin/invites`.
- Local notification prefs + muted thread ids in `~/.mutande/notification_prefs.json`; inbox watch (~30s) shows metadata-only OS banners when agents have new mail and no host turn is running.
- RPC `install_skill` writes Cursor/ChatGPT skill paths or stages Claude ZIP under `~/.mutande/skills/`; skill status lives beside MCP outcomes in `~/.mutande/host_links.json`. Hub catalog is public mutande-ai `skills/catalog.json` (raw GitHub); daemon caches catalog + skill bodies under `~/.mutande/hub_skills/` (serve stale on fetch fail; warn when cache age > 7 days; Claude Hub installs use the same ZIP/manual path with a prominent instruction card).
- Large payloads use private R2 with object key prefix `blobs/{id}` (`R2_*` hub env); on open, core materializes full decrypted artifacts to `~/.mutande/blob_cache/` and exposes `resources[].path` (+ size) for agents — never stub as “too large to inline”. Public installers ship Mac + Windows together to `mutande-releases` at `https://downloads.mutande.online` (Mac: notarized DMG via `scripts/release-macos-dmg.sh` then `scripts/upload-downloads-r2.sh`; Windows: Actions `Release Windows alpha` / `publish-r2` → `mutande-alpha-windows-setup.exe` primary + zip fallback; `R2_DOWNLOADS_*` — not hub blobs tokens). Mac app bundle id `ai.mutande.app` bundles `mutande-core` sidecar in Resources; site `/download` gates Intel/Windows via `NEXT_PUBLIC_*_PUBLISHED`; local `web/public/downloads/*` gitignored only.
- Flutter thinking UI uses a single **working** orb (tilted particle orbits) for all loading states; loading CTAs morph button ↔ orb.
- Agent addresses use `handle/agent` (`alice@acme/claude`); bare handle is the default agent; never show `/default` as a user-facing address; always display handles and agent slugs lowercase in UI (`alice@acme/cursor`, not `Alice@…` or `/Cursor`); for self-collaboration allow short `@agent` (e.g. `@claude`); cannot hand off / `forward_blob` to the same agent slug as the MCP connection — errors should suggest a different peer; personal `@all` means one shared group thread among the user's own agents and may carry questions (distinct from org broadcast `@all@acme`, which must not carry question payloads). Day-one success is MCP `ping` (`health` = daemon auto-pong; `thread` = real Threads mail agents reply to), typically targeting personal `@all`.
- Public docs at `/docs` via Nextra in `web/`, same Vercel deploy as marketing/auth; security writeups may link technologies and describe E2E at a high level without revealing proprietary crypto IP. Landing product frame is **Address Intelligence** (trusted org addresses for people/assistants/services — identities, not implementations); intro is Remotion in `video/` (1080², ~28s muted seamless loop beside copy, not a trailer — ELI5 / Apple-style explainers; alice/bob-style demo addresses, not personal names); ship silent web-friendly encodes via `video/` `npm run ship` (H.264 Main/`yuv420p` MP4 required, optional WebM; prefer ~30fps for hero playback) into `web/public/brand/` then R2 `downloads.mutande.online/brand/` (`scripts/upload-brand-r2.sh`).
- Thread messages nest via bundle `in_reply_to` and hub `parent_message_id`; `forward_blob` can continue an existing thread via optional `thread_id` / `in_reply_to` (omit `recipient` when replying — not always a new thread). Agent upvotes (up-only, one per agent_id, toggle) signal coordination weight on a message; MCP tool `upvote_message`.

## Cursor Cloud specific instructions

This runs on a **Linux** VM. The Flutter `app/` is macOS-only — it cannot build or run here (Flutter/Dart is not installed); its onboarding role is substituted by daemon RPC / hub calls when needed. Runnable on Linux: `core/` (Rust), `hub/` + `mcp/` + `pilot/ops/` (Deno), `web/` (Next.js/pnpm), `video/` + `video-mc/` (Node).

Toolchains (preinstalled in the environment; the update script only refreshes project deps): Rust **stable ≥ 1.85** is required — a transitive dep (`idna_adapter`) needs edition 2024, so the default Ubuntu 1.83 fails; this VM uses rustup `stable` (1.97). Deno **≥ 2.9** is required — `hub/deno.lock` / `mcp/deno.lock` are lockfile v5 (Deno 2.1 cannot read them). Node 22 + pnpm 10 (`web/` is **pnpm only**).

Run services (see also root `README.md`, `hub/README.md`, `core/README.md`):
- Hub: `cd hub && deno task dev` → `:8000`; `GET /health` and `POST /v1/waitlist` are public. Authed routes return 401 locally because `AUTH0_DOMAIN`/`AUTH0_AUDIENCE` are unset (no real Auth0 tenant); this is expected, not a bug. Hub tests: `deno task test`; type-check: `deno task check`.
- Web: requires a gitignored `web/.env.local` to boot dev. Minimum: `AUTH0_DOMAIN`, `AUTH0_CLIENT_ID`, `AUTH0_CLIENT_SECRET`, `AUTH0_SECRET` (any 32-byte hex), `AUTH0_AUDIENCE`, and `MUTANDE_HUB_URL=http://localhost:8000` to point the waitlist proxy at the local hub. Then `cd web && pnpm dev` → `:3000`. Dummy Auth0 values are fine for public pages (landing, `/waitlist`); real Auth0 secrets are only needed for login/onboarding/admin/ops pages. The waitlist form posts to Next `/api/waitlist`, which proxies to `${MUTANDE_HUB_URL}/v1/waitlist`.
- Core daemon/MCP: `cd core && cargo run -- serve` (socket + `127.0.0.1:3847` HTTP bridge, bearer from `~/.mutande/daemon_http_token`) and `cargo run -- mcp` (stdio). A full live MCP `ping` (agent-mail over the hub) needs onboarding via **real Auth0 credentials**; without them, the hub store tests + the `createApp(kv, { verifier })` test-verifier seam cover the courier flow end-to-end.

Known pre-existing breakages on `main` (NOT environment issues — do not attribute to your setup): `core/` does not compile (e.g. `OpenedThreadMessage` constructors in `daemon/state.rs` omit `receipts`/`task_pending_approval`; `Contact.user_id`; awaiting `Vec` type mismatch), which also blocks `cargo test`/`cargo clippy`. `hub` `deno task test` has 2 failing assertions in `store/store_test.ts` (reply `from_handle`, bare `@all` group thread). `web` `pnpm build`/`pnpm lint` fail on pre-existing app errors (`ops-dashboard.tsx` chart.js `BarElement.base` type; a few eslint errors); use `pnpm dev` for local development.
